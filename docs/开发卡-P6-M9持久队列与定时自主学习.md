# 开发卡：P6 / M9 持久队列与定时自主学习

## 目标

把当前依赖 Python 进程内后台线程的长任务迁移到统一、可恢复的持久队列，同时保持 `React + Python HTTP + SQLite` 的本地工作台继续可用，并提供可选的 Redis / Celery 执行后端。

```text
浏览器/API
→ 创建业务运行记录
→ 写入 durable_task_queue
→ Local Worker（默认）或 Celery Worker（可选）
→ 调用受保护的内部执行入口
→ 业务检查点/工具审计
→ 完成或指数退避重试
```

PostgreSQL 的业务数据迁移与 SQLite 队列切换分开实施：本阶段先稳定执行边界和任务契约，避免一次性改写现有数百个 SQLite 查询。

## 本阶段范围

- 新增长任务持久队列表、幂等键、尝试次数、可执行时间、租约、Celery 任务编号与错误摘要。
- 统一接管竞品目录采集、采集内容学习、周期竞品学习、内容 Agent 与 GSC 反馈 Agent 的后台分发。
- 默认 `local` 后端使用持久队列 Worker；服务重启后恢复 `running`、`retry_wait` 和 `queued` 任务。
- 可通过 `SEO_TASK_QUEUE_BACKEND=celery` 切换 Redis / Celery 投递；Celery 只调用受保护的工作台内部执行入口，不直接读取 SQLite 或模型配置。
- 周期学习调度器只负责产生队列任务，不直接开业务执行线程。
- 系统任务页显示队列记录、尝试次数和最近错误。

## 不在本阶段范围

- 不自动公开发布 WordPress 内容。
- 不取消蓝图审批、发布审批、robots 或高风险事实门禁。
- 不在同一提交中把全部 SQLite SQL 改写为 PostgreSQL SQL。
- 不把 API Key、Cookie、OAuth token 或 WordPress 密码放入队列载荷。

## 数据与幂等

Migration 43 新增 `durable_task_queue`：

- `project_id`：强制项目边界。
- `task_type`：白名单任务类型。
- `resource_id`：对应业务运行或 Agent Job。
- `dedup_key`：同一业务动作只允许一个活动队列项。
- `status`：`queued / running / retry_wait / completed / failed / cancelled`。
- `attempt_count / max_attempts / available_at`：指数退避与上限。
- `lease_expires_at`：服务中断后的恢复依据。
- `payload_json`：只保存非敏感执行参数。
- `celery_task_id`：可选外部投递追踪。

## 配置

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `SEO_TASK_QUEUE_BACKEND` | `local` | `local` 或 `celery` |
| `SEO_LOCAL_WORKER_CONCURRENCY` | `2` | 单机 Worker 并发上限 |
| `SEO_WORKER_TOKEN` | 启动时随机值 | 保护内部执行入口；Celery 模式必须显式配置 |
| `SEO_WORKSPACE_CALLBACK_URL` | 当前服务地址 | Celery Worker 回调工作台地址 |
| `REDIS_URL` | `redis://127.0.0.1:6379/0` | Celery broker/result backend |

## 失败、恢复与安全

- 执行前用条件更新领取任务，重复 Worker 不能重复领取。
- 失败按 5、15、45 分钟退避，达到上限后转为 `failed`。
- 启动时把过期租约和遗留 `running` 任务恢复为 `retry_wait`。
- 内部执行入口要求 `X-SEO-Worker-Token`，并再次校验队列项、业务资源和 `project_id`。
- 队列仅保存任务类型、资源编号和非敏感摘要；外部凭据仍由服务端配置读取。

## PostgreSQL 迁移门槛

完成本阶段后再按 Repository 分批迁移业务表：项目与配置 → 采集与资料 → 记忆 → 内容与审批 → GSC。每批必须提供 SQLite/PostgreSQL 双实现、数据校验脚本和回滚快照；前端与 Agent 工具契约保持不变。

## 验收标准

- 关闭并重启服务后，未完成队列项可以继续执行。
- 同一业务运行重复入队返回原活动队列项，不重复采集或生成。
- 执行失败会进入 `retry_wait`，记录错误且不泄露密钥。
- 周期学习到期后生成 `scheduled` 业务运行和一个持久队列项。
- 项目 A 不能查询或执行项目 B 的队列项。
- 未携带 Worker Token 不能调用内部执行入口。
- `python -m unittest discover -s tests -q` 与 `npm run build` 通过。
