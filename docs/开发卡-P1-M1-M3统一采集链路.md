# 开发卡：P1 / M1–M3 统一采集链路

## 目标

在现有 React + Python HTTP + SQLite 工作台中，统一“域名/关键词发现 → URL 规范化与去重 → 正文采集 → 采集内容库 → 失败重试与断点恢复”。保留现有竞品研究、内容学习和一键采集入口，不重写已稳定功能。

## 本阶段范围

- M1：以项目为边界保存域名、关键词和一方资料采集计划。
- M2：所有发现 URL 使用规范 URL 去重，并为每次批量采集建立逐 URL 执行项。
- M3：正文保存不可变版本；当前内容库继续提供最新版本投影；服务重启后恢复未完成采集项。
- 现有 `/api/competitor-url-catalog/*` API 保持兼容并返回新增进度字段。
- 系统任务中心继续使用现有批次任务，并可查看逐项统计。

## 不在本阶段范围

- 不迁移 PostgreSQL、Redis 或 Celery；SQLite 与本机后台线程仍是当前执行适配器。
- 不绕过 robots.txt、登录、验证码或付费墙。
- 不自动公开发布内容。
- 不在本阶段完成写法卡、事实卡、蓝图、写作与发布的全部 Agent 节点。

## 输入与输出

输入：`project_id`、发现来源类型（`domain`、`keyword`、`first_party`）、来源值、规范化 URL、公开页面正文和提取器名称。

输出：采集计划、URL 目录、采集批次、逐 URL 状态、正文版本、当前正文投影和可恢复检查点。

## Migration 39

- `collection_plans`：项目内采集来源与配置。
- `collection_run_items`：每个批次中每个规范 URL 的独立状态、尝试次数、错误和正文版本引用。
- `competitor_content_versions`：同一内容记录按正文哈希保存不可变版本。
- `competitor_catalog_collection_runs` 新增 `unchanged_count`、`recovered_count` 与 `last_heartbeat_at`。
- 迁移时为现有正文补建首个版本，不改变 `competitor_content_memory` 的主键和现有引用。

## API 契约

- `GET /api/collection-plans?project_id={id}`：读取项目采集计划。
- `POST /api/collection-plans`：创建或更新项目采集计划。
- `GET /api/competitor-url-catalog/collection-runs?project_id={id}`：批次中包含逐项统计。
- `GET /api/competitor-url-catalog/collection-runs/{run_id}/items?project_id={id}`：读取逐 URL 检查点。
- `POST /api/competitor-url-catalog/collect`：兼容入口，创建批次与逐 URL 执行项。
- `POST /api/competitor-url-catalog/collection-runs/{run_id}/execute`：只执行该项目、该批次尚未完成的执行项。

## Agent 工具边界

本阶段采集能力只通过服务端统一采集服务调用。后续 Agent 工具 `research_competitors` 使用该服务，不直接访问数据库、爬虫或任意项目的 URL。

## 幂等规则

- URL 唯一键：`(project_id, normalized_url)`。
- 批次执行项唯一键：`(run_id, normalized_url)`。
- 正文版本唯一键：`(memory_id, content_hash)`。
- 同 URL、同正文哈希：不新增版本，只刷新当前投影的 `last_captured_at`，执行项记为 `unchanged`。
- 同 URL、正文哈希变化：新增版本，更新当前投影并重建正文分块。
- 已成功入库 URL 默认不再次加入“一键采集”；失败项可在后续批次重试。

## 状态与恢复

执行项状态：`queued`、`running`、`collected`、`unchanged`、`robots_blocked`、`excluded`、`failed`。

- 每个 URL 在开始前写入 `running` 和尝试次数，结束后独立提交。
- 单项失败不回滚其他成功项。
- 服务启动时把遗留 `running` 执行项恢复为 `queued`，把对应批次恢复为 `queued` 并继续派发。
- 已完成的 `collected`、`unchanged`、`robots_blocked` 和 `excluded` 项不会因恢复被重复执行。

## 项目隔离与安全

- 计划、目录、批次、执行项、正文和版本都保存 `project_id`。
- API 和服务层均二次校验资源归属；跨项目访问返回拒绝，不用仅凭资源 ID 查询。
- 爬虫继续强制尊重 robots.txt；受限页面只保存 URL 和原因，不保存正文。
- 错误摘要截断保存，不记录密码、Cookie、Token 或 API Key。

## 测试与验收

- 同 URL 同正文不新增版本。
- 同 URL 正文变化时新增版本并更新当前投影。
- 跨项目不能读取或执行其他项目的批次和执行项。
- 遗留 `running` 批次和执行项在服务启动后恢复。
- 单个失败只重试失败 URL，已成功 URL 不重复采集。
- 现有竞品采集、学习、发布门禁回归测试全部通过。
- React 构建通过；采集页、采集内容库和系统任务页可正常加载。
