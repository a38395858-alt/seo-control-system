## 项目隔离与断链处理

- 27 张 PostgreSQL 目标表都显式保存 `project_id`。
- Brief、Outline、章节、Agent Step、记忆使用链和 GSC 查询明细通过受控的父表 JOIN 推导项目。
- `content_assets` 的当前 Brief/Outline/Draft/Run 指针以及 `content_drafts.parent_draft_id` 保留原值，本批暂不建立循环/自引用外键；最终切换阶段再增加延迟约束。
- 其余父子关系使用目标表外键，迁移顺序不可由模型或前端改写。

## 凭据安全

- `project_wordpress_configs.application_password` 不读入迁移快照、不写 PostgreSQL、不出现在校验报告。
- WordPress 目标仅保存站点、用户名与 `requires_reauthorization`；切换时由用户重新输入应用密码。
- 全局 `gsc_oauth_connection.refresh_token` 不纳入通用数据迁移；GSC 在新环境重新 OAuth 授权。
- 凭据不可通过 mismatch、dry-run、日志或 Agent 工具返回。

## CLI

```text
migrate-workflow-postgres [--apply]
validate-workflow-postgres
```

未传 `--apply` 时只生成 SQLite 预览，不连接 PostgreSQL。

## 验收结果

- 27 张表支持 dry-run、单事务批量幂等 apply 和逐字段 validate。
- JSON、UTC 秒级时间、数值和复合/非 `id` 主键均进行规范化。
- 缺失、额外和 mismatch 报告包含源表与主键。
- 项目归属推导、跨项目隔离和凭据脱敏已有测试。
- 真实 SQLite 只读预览：`source_count=946`、`applied=false`。
- 真实 946 条快照的内存目标完整校验：`valid=true`，不包含 WordPress 应用密码或 GSC refresh token。
- P6.5 定向测试 5 项通过；全量 Python 回归 307 项通过、4 项跳过。
- React/TypeScript 检查与 Vite 生产构建通过。
- 未执行 PostgreSQL `--apply`，SQLite 仍为 8000 工作台唯一正式业务源。
