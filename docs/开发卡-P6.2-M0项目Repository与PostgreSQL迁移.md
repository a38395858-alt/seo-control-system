# 开发卡：P6.2 / M0 项目 Repository 与 PostgreSQL 迁移

状态：已完成（2026-07-31）

## 目标

先把项目主数据从 `web.py` 的内联 SQL 中抽离，建立 SQLite/PostgreSQL 共享的 Repository 契约和可重复执行的数据迁移校验，为后续关键词、采集、记忆、内容、审批与 GSC 分批迁移提供标准模板。

## 本阶段范围

- 项目创建、列表、摘要、更新、删除改由 `ProjectRepository` 执行。
- `SQLiteProjectRepository` 保持当前 `http://127.0.0.1:8000` 行为和真实聚合统计。
- `PostgresProjectRepository` 使用独立 `workspace_projects` 表，保留原 `project_id`，支持幂等 upsert。
- `ProjectMigrationService` 支持 SQLite → PostgreSQL 全量同步及逐字段校验。
- CLI 提供 `migrate-projects-postgres` 和 `validate-projects-postgres`；未显式传入 `--apply` 时只预览，不写 PostgreSQL。
- PostgreSQL 密码只从 `DATABASE_URL`/命令参数读取，不进入日志、SQLite 或迁移报告。

## 不在本阶段范围

- 不把关键词、内容、记忆和任务表一起迁移。
- 不允许前端切换 PostgreSQL 项目后继续访问仍在 SQLite 的子资源。
- 不启用自动双写；正式切换前仍以 SQLite 为唯一业务源。
- 不删除或修改现有 `platform_api.websites` 数据。

## Repository 契约

```text
create_project
list_projects
list_project_summaries
update_project
delete_project
upsert_project_snapshot
```

项目快照字段固定为：ID、名称、网站地址、行业、国家、语言、创建/更新时间、关键词数、已选标题数、内容数、知识库数和最新内容状态。

## PostgreSQL 表

`workspace_projects` 是现有工作台项目的迁移目标，不复用 `platform_api.websites`：后者属于新版网站控制平面，字段语义和生命周期不同。两个表后续通过 `workspace_project_id` 显式映射，禁止仅按域名猜测关联。

## 迁移与回滚

1. 初始化 PostgreSQL 目标表。
2. 从 SQLite 读取一致性快照。
3. 按原 ID 幂等 upsert。
4. 校验记录数和所有业务字段。
5. 只有零差异才允许进入下一模块迁移。

本阶段不改变 SQLite；回滚只需停止使用 PostgreSQL 镜像表。迁移命令不得删除 PostgreSQL 中不属于当前 SQLite 快照的项目。

## 验收标准

- 项目 API 行为与现有测试一致。
- SQLite Repository 的摘要计数来自真实关联表。
- 同一快照重复迁移不会产生重复项目。
- 验证报告能指出缺失、额外及字段不一致项目。
- PostgreSQL 不可用时，8000/SQLite 工作台不受影响。
- 全量 Python 测试与 React 构建通过。

## 已交付

- 新增 `ProjectRepository` 契约，以及 SQLite、PostgreSQL 两套项目 Repository。
- 项目创建、列表、真实聚合摘要、更新和删除 API 已从 `web.py` 内联 SQL 切换为 Repository 调用。
- PostgreSQL 新增独立 `workspace_projects` 目标表，迁移时保留 SQLite 原始项目 ID，并在迁移后校准自增序列。
- 新增预览、应用和逐字段校验命令；预览模式不连接或写入 PostgreSQL，校验差异时返回非零退出码。
- 时间戳校验统一换算为 UTC 秒级格式，兼容 SQLite 无时区文本和 PostgreSQL `TIMESTAMPTZ`。
- 迁移支持幂等 upsert，并报告缺失项目、额外项目及具体字段差异。
- PostgreSQL 初始化采用实例级缓存；空源数据库执行迁移时也能安全初始化目标表和序列。
