# 模块 3：GPT / DeepSeek 模型路由与随时切换

## 目标

让用户在内容生产中明确选择 GPT 或 DeepSeek；后台保留默认智能路由，但不隐藏实际使用模型。

## 页面选择器

```text
写作模型：[GPT-5.6 高质量] [GPT-5.6 平衡] [DeepSeek 高效]
审稿模型：[跟随写作模型] [GPT-5.6] [DeepSeek]
```

选择器应用于 Brief、大纲、全文、单个 H2 重写和审稿；默认保存为当前项目最近一次选择。

## 默认路由

| 工作 | 默认角色 |
|---|---|
| 任务计划、内容蓝图、最终正文、最终 QA | GPT-5.6 |
| 竞品结构提取、写法卡、批量标签、表格候选 | DeepSeek |
| 高价值商业文章 | GPT-5.6 高质量 |
| 高量常规初稿 | DeepSeek 初稿 + GPT-5.6 定向改写 |

## 切换行为

1. 切换只影响下一个尚未启动的节点，不中断进行中的请求。
2. 点击重新生成才创建新 draft version，旧版本永久保留用于比较和回退。
3. 同一文章可有 DeepSeek 初稿和 GPT 改写版；版本与 H2 层级均记录实际模型。
4. 不允许成本策略静默降级最终写作模型。

## 数据与接口

- `agent_jobs.input_json` 保存用户选择的 `writer_model`、`reviewer_model`。
- `agent_steps` 保存每个节点实际 `model_provider` 与 `model`。
- 内容详情接口返回版本模型链，如 `DeepSeek → GPT-5.6`。

## 验收标准

- 用户可在页面直接切换，并在新任务中看到选择生效。
- 同一文章至少可比较两个不同模型版本。
- 系统任务和文章详情均不再只显示笼统“AI 生成”。
