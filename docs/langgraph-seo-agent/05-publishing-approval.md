# 模块 5：发布审批与 WordPress

## 目标

让智能体参与发布检查和发起请求，但把凭据、媒体上传和最终外部写入牢牢放在现有后端。

## 发布分工

| 操作 | 执行者 |
|---|---|
| 内容、链接、图片、标签、表格检查 | GPT/DeepSeek/Hermes（受控） |
| 生成发布建议与门禁清单 | LangGraph |
| 用户选择草稿或公开发布 | 前端用户 |
| 解密 WordPress 配置、上传 WebP、创建/更新文章 | `web.py` 后端 |
| 保存文章 ID、URL、状态、错误 | `content_wordpress_publications` |

## 发布门禁

1. 内容和图片属于当前项目，且为当前 draft。
2. 产品事实来自项目知识库；外部来源与段落主题匹配。
3. 图片已生成或用户明确选择无图；本地文件可读取。
4. HTML 表格、内链、nofollow 外链和 tags 均通过检查。
5. 当前项目 WordPress 配置已测试，且账号具有对应权限。

## 审批级别

- 默认：草稿和公开发布均要求确认。
- 可选：自动创建草稿，公开发布仍需确认。
- 高信任项目：项目设置显式开启后允许自动公开；保留完整审计和失败提示。

## 接口建议

- `POST /api/approvals/:id`：批准或拒绝发布。
- 已批准后复用现有 `/api/content-assets/:id/publish-wordpress`，只允许后端调用。
- 返回 `wordpress_post_id`、`wordpress_url`、状态和可操作错误摘要。

## 验收标准

- 模型无法读取密码、执行未经批准的公开发布或跨项目发布。
- 发布完成后任务页和内容页都显示成功链接。
- 403、媒体权限、nonce 过期等错误可原样归类并指导下一步。
