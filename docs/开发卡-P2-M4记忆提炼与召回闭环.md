# P2 / M4：记忆提炼与召回闭环

## 本阶段结果

把已采集竞品正文自动提炼为三类可治理、可解释、可追溯的学习卡，并让内容生产与 Agent 召回同一套项目内记忆。

## 三类卡

| card_type | 中文名称 | memory_type | 用途 |
|---|---|---|---|
| `writing_style` | 写法卡 | `style` | 学习解释顺序、表达方法、读者决策路径 |
| `content_structure` | 结构卡 | `editorial` | 学习章节组织、问题展开与信息格式 |
| `topic_gap` | 选题缺口卡 | `editorial` | 记录多个来源共同遗漏、值得补充的覆盖方向 |

竞品卡不得写入 `fact`。竞品中的价格、认证、法规、参数和结论都不是本项目品牌事实。

## 数据契约

每张模型候选卡必须包含：`card_type`、`topic`、`summary`、至少一个当前批次中真实存在的 `source_id`、`quality_score`、`confidence_score`。`applicability` 可包含搜索意图、内容类型和主题范围。

服务端不信任模型输出：重新校验 `project_id`、来源记录、正文是否存在以及正文版本；缺失或跨项目来源直接拒绝。保存时写入来源 URL、正文哈希、不可变版本 ID、采集时间与学习任务 ID，不保存大段竞品原文。

## 幂等与治理

- 同项目 + 卡类型 + 规范化主题 + 来源集合形成稳定签名。
- 重复学习更新原卡，不重复创建。
- 历史版本的竞品学习记忆自动归类为写法卡；首次新学习会就地升级旧签名。
- 同一来源出现新正文哈希时追加证据版本并刷新卡片验证时间。
- 卡片保留质量、置信度、时效状态、适用范围、证据数量与推理级别。
- 后续治理任务可将低质量、冲突或过期卡标为 `needs_review`、降权、停用或被新卡取代。

## 召回门禁

- 必须属于当前项目且为启用状态。
- 必须与标题或关键词有主题交集；置顶不能绕过主题边界。
- 返回卡类型、置信度、时效、证据数量、来源和选择原因。
- 每次内容使用仍写入 `content_memory_links`，供人工反馈和效果评估追踪。

## 验收标准

1. 三类卡可分别保存，旧模型未返回 `card_type` 时兼容为写法卡。
2. 无真实来源、跨项目来源、未知卡类型均拒绝。
3. 重复运行不重复建卡；正文版本变化可追加证据。
4. 竞品输出不能写成事实记忆。
5. 内容生产和 Agent 工具都返回相同的可解释证据字段。
6. 工作台可看到三类卡数量、最近学习结果、置信度与来源。
