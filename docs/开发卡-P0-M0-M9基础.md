# 开发卡：P0 / M0 项目边界与 M9 Agent 调度基础

## 目标

在现有 React + Python HTTP + SQLite 工作台内建立可继续扩展的 Agent 基础：项目隔离、服务端工具白名单、工具审计、任务检查点，以及暂停、恢复、重试和取消操作。

## 不在本次范围内

- 不完成竞品采集、写法卡、蓝图、写作、QA、发布和 GSC 的全部 Agent 节点。
- 不迁移 PostgreSQL、Redis 或 Celery。
- 不允许模型直连数据库、文件系统、WordPress 或 GSC。

## 输入与输出

- 输入：`project_id`、可选 `content_asset_id`、`requested_action`、写作与审核模型路由。
- 输出：Agent 作业、节点记录、检查点、工具审计、状态和可恢复节点。

## 数据表与迁移

- Migration 38 扩展 `agent_jobs`、`agent_steps` 的检查点、输入、耗时、Token、成本和提示词版本字段。
- 新增 `agent_tool_audits`，保存成功与失败的工具调用审计。

## API

- `POST /api/agent-jobs`
- `GET /api/agent-jobs`
- `GET /api/agent-jobs/{id}`
- `POST /api/agent-jobs/{id}/pause`
- `POST /api/agent-jobs/{id}/resume`
- `POST /api/agent-jobs/{id}/retry`
- `POST /api/agent-jobs/{id}/cancel`

## Agent 工具

- `load_project_context`
- `retrieve_project_memories`

所有工具均由 `AgentToolService` 调用，并再次核对作业与项目归属。

## 页面入口

- `/system-tasks`

统一展示关键词、标题、内容、采集、学习、WordPress 和 Agent 作业；Agent 作业可查看节点和工具审计，并按状态执行暂停、恢复、重试或取消。

## 幂等与恢复

- 作业检查点保存最近持久化节点。
- 暂停不覆盖原恢复节点。
- 恢复和重试从检查点重新排队，不从头伪造已完成步骤。

## 权限与项目隔离

- API、作业和工具均校验 `project_id`。
- 跨项目读取作业、内容资产或记忆时拒绝请求。
- 工具输入输出审计对 Key、Token、Password 等字段脱敏。

## 测试与验收

- Agent 工作流、作业 API、工具审计和项目隔离测试通过。
- 发布门禁回归通过，未因兼容旧状态而放宽事实来源要求。
- React 构建通过。
- `/system-tasks` 可真实加载任务、筛选、展开详情并执行合法动作。
