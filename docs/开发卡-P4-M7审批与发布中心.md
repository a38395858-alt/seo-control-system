# 开发卡：P4 / M7 审批与发布中心

## 目标

把内容 Agent 的当前正文送入不可绕过的发布安全链路：

```text
当前正文
→ 发布前门禁
→ 持久化发布申请
→ 人工批准或拒绝
→ 后端读取当前项目 WordPress 凭据
→ 创建草稿或公开发布
→ 回写文章 ID、URL、状态和错误
```

模型、前端和 Agent 均不能读取 WordPress 密码，也不能绕过批准接口直接写入网站。

## 模块边界

- `prepare-publish` 只做本地校验和创建审批，不连接 WordPress。
- `agent_approval_requests` 保存人工决定；批准绑定项目、内容、正文版本和发布方式。
- `publish-wordpress` 只接受尚未消费的一次性批准，并在写入前重新运行门禁。
- WordPress 凭据只在后端解密；API、任务输入、工具审计和错误信息均不得返回密码。
- 默认发布方式是 WordPress 草稿；公开发布必须再次明确确认。

## 发布门禁

门禁必须检查：

1. 当前正文属于当前项目和内容资产；
2. QA 已通过，且没有待验证事实；
3. 标题和 50–180 字符 Meta Description 完整；
4. 保留 2–3 个有效英文标签；
5. Markdown 表格可转换为 HTML；
6. 正文没有不安全或不支持的链接协议；
7. H2 配图已生成且本地文件可读，或用户明确确认无图；
8. 当前项目 WordPress 连接已成功测试；
9. 正文不与本项目另一篇已公开文章完全重复。

任何阻断项存在时不得创建批准，也不得访问 WordPress。

## 审批与幂等

- 同一项目、内容、正文版本和发布方式的重复申请复用未处理审批。
- 正文版本或发布方式变化后，旧批准自动失效。
- 批准只能消费一次；重复调用不得产生第二次外部写入。
- 用户取消或拒绝时，任务进入取消状态，门禁报告和步骤审计保留。
- WordPress 写入失败时记录失败阶段和可操作错误；重新发布必须重新走门禁和人工批准。

## 前端交付

- 内容库、文章阅读页和配图页均显示“检查并申请发布”。
- 发布方式明确区分“创建 WordPress 草稿”和“公开发布（需人工确认）”。
- 任务中心分别展示蓝图审批和发布审批。
- 发布审批展示门禁逐项结果、正文版本、目标状态、拒绝和批准按钮。
- 成功后展示 WordPress 文章 ID 与可打开 URL。

## 验收标准

- 未审批、跨项目、已拒绝、已消费、旧正文版本的批准均不能发布。
- 发布执行前重新运行门禁，状态变化后立即阻断。
- 重复准备不会产生重复待审批任务。
- 取消确认不会留下无人处理的待审批记录。
- 任务详情和 API 响应不包含 WordPress 密码。
- React 构建、发布门禁测试和全量 Python 测试通过。
